# 自己动手验收

先访问本机 `http://127.0.0.1:3000`；公网演示地址以 `var/public-demo/state.json` 的 `url` 为准。公网先输入 `var/public-access.txt` 的入口账号密码，负责人登录另用 `var/local-admin.txt`。两套密码都不要提交到代码库。卖家使用自己注册的账号，和这两套密码分开。

请使用新版Chrome/Edge或Safari 16.4及以上，并启用JavaScript。本机原Safari 16.3不能正常运行交互；现在建单页会提示升级。表单交互加载完成后才能输入和提交。建单时先填写自由文本明细；订单内补充属性时才逐项勾选“我已核实”，商品说明可直接补充，不需要逐项填写固定参数。

先打开 `/seller/register`，填写称呼和可收信的邮箱，点击“获取验证码”，输入收到的6位数字；密码8–18位，英文字母、数字、特殊符号至少两类。验证邮箱并注册后自动登录。以后从 `/seller/login` 登录，在 `/seller/orders`（顶部“我的订单”）找回全部订单；换浏览器或重启不影响数据库中的订单。所有新订单都必须登录才能提交，并自动归属当前账号。验证码10分钟有效，60秒后可重发；目前未提供忘记密码功能，请记住密码。QQ发件配置见 `EMAIL_SETUP.md`。旧订单及图片已清空，不提供旧单认领。

建单页合并原01、02部分，商家称呼与邮箱由账号自动关联，无需重复填写。只提供商品名字、商品明细信息、可选国内平台商品链接、商品参考图、补充商品说明与期望卖点五项。顾问会尝试读取公开商品页，遇到登录或验证页面时如实提示。第02部分可选择或复制粘贴一张商品参考图（PNG/JPEG/WebP，最多10 MiB），点击“保存资料，创建订单”时自动上传。成功后页面会切换为“资料已保存”和私有链接，点击“查看订单进度”进入订单。若订单已创建但图片上传失败，使用“重试上传参考图”或进入订单补图，不需要重新建单；其他提交错误会显示在表单顶部。

密码超过18位会明确提示并拒绝注册，不截断后保存。旧版注册页曾把超过12位的输入截为前12位；这类旧账号可先用原密码前12位登录，更新规则不会自动补回或修改已有密码。

订单详情中的参考图提供“删除参考图”→“确认删除”。未用于制作且没有生产任务占用的参考图可删除；已成为生成图片依据的参考图随历史版本保留，页面会说明不能删除的原因，可上传新图用于后续版本。成品图片随交付版本保留。

“给这份订单留个消息”由获客Agent处理，发送后会显示已保存和处理状态，回复出现在沟通记录中。“联系人工协助”会转交负责人并暂停自动获客回复；此时聊天区会显示暂停原因。负责人在人工客服中回复并勾选“回复后结束本次人工处理”，才会解除暂停并恢复资料审查。不要把转人工当作催促AI回复的按钮。

负责人从网页底部“负责人入口”或 `/internal/login` 登录，进入 `/internal/orders` 选择订单；资料审查通过后在订单详情右侧“接单决定”批准或拒绝。资料未齐时可查看记录和人工回复，补齐后再接单；生成完成后另行审核版本并放行交付。负责人账号和密码保存在本机 `var/local-admin.txt`。登录页账号固定为 `owner`，密码只复制 `password=` 右侧的完整值，不要带前缀或把文件两行一起粘贴；这与卖家密码、SMTP授权码分开。

公网版仍由本机运行，电脑或隧道停止后地址不可用；它有独立数据库，所以不会自动显示本机开发版的历史订单。两边都是实际 MiMo + 模拟发布，人工测试会消耗模型额度；自动测试使用离线模型。

## 一条完整订单

建议用两个浏览器窗口：普通窗口扮演卖家，无痕窗口扮演负责人（公网版两边都要先输入入口密码）。

| 步骤 | 你怎么操作 | 应看到什么 |
|---|---|---|
| 1 建单 | 先注册或登录卖家账号，首页点“提交商品资料”，填写商品名与已有明细，如球衣的蓝白配色、主题；可选商品链接、图片和期望卖点 | 建单成功，自动保存到“我的订单”；进入详情后刷新仍能访问 |
| 2 初审 | 进入订单，等待获客顾问分析现有描述、实际图片和可访问链接；需要时通过聊天或自由文本补充说明 | 显示自然中文分析与文案方向，不强制索取固定参数；初审后负责人可批准或拒绝 |
| 3 接单 | 另一窗口打开 `/internal/login`，登录后在列表找到本单，点“提交接单批准” | 先显示入队，再进入研究、生成、审校；需要等真实模型响应 |
| 4 审核 | 查看研究包、正文、声明依据、实际图片与审校；可填具体否决原因后点“否决本版”，观察新版本 | 旧版保留；查看旧版时不能放行最新版。只有完整图文审校通过的当前版本才能放行 |
| 5 交付 | 负责人点“本版放行并交付”，回到卖家窗口 | 出现已放行文案、两张实际PNG和“下载本版 ZIP”；放行前不能下载草稿 |
| 6 返修 | 卖家在反馈内容填写“标题更简洁，全部商品事实保持不变”，提交；负责人等新版本完成，再审核放行 | 新版本保留版本链，卖家需要检查新交付；旧确认不能用于新版本 |
| 7 模拟发布 | 卖家先切到最新交付版，填写示例售价12.99 USD和自定义SKU，勾选明确确认，再点“确认本版并模拟上架” | 先入队，之后在订单中显示模拟刊登完成；不会提供匿名公开商品页 |
| 8 人工支持 | 卖家点转交人工处理；负责人在人工客服中回复、勾选结束本次处理 | 卖家看到回复；接管时自动资料回复暂停，结束后解除暂停 |

完整测试资料（只用于虚构示例）：

| 字段 | 值 |
|---|---|
| 商品名 | 桌面理线夹 / Silicone Desk Cable Clips |
| 材质 | silicone |
| 包装数量 | 6，单位 pieces |
| 尺寸 | 4 x 3 x 2，单位 cm |
| 测量口径 | each individual cable clip（单件） |
| 适用线径 | 6，单位 mm |
| 颜色 | black |
| 适用范围 | Organizing desk cables up to 6 mm in diameter |

获客顾问直接分析现有资料，订单内展示初审判断、图片观察、链接读取状态和内容方向；不要求把原文重新抄进参数表。负责人在“商品图片与参考素材”区域只能查看，不能上传或删除。正式研究包在批准接单后生成，尚未批准时页面应解释原因。具体规则见[输入策略](AGENT_INPUT_STRATEGY.md)。

上方参数表是可选的完整测试样例，不是所有商品的必填清单。没有外部竞品价格证据时不提供可靠价格区间；自动竞品采集尚未接入。初审是资料合理性判断，不能凭照片或链接保证商品真伪。

## 三个关键分支

- **数量与尺寸分开：**卖家反馈时勾选“同时更新商品事实”，把包装数量6改4，保持6 mm线径不变，并提供真实对应4件的参考图。新图若仍有6个，应该请求更换或停止交付，不能只改角标掩盖主体数量。
- **账号与权限：**卖家从“我的订单”退出，再用新浏览器登录同一账号，应找回之前的订单并打开详情。注册第二个账号，其列表应为空；即使打开第一个账号的完整订单链接，也不能看到订单、私图或ZIP。公网入口密码不代替卖家账号或负责人登录。
- **技术恢复：**负责人核实失败原因后可授权恢复；成功步骤与预算保留，不保证质量超限的任务可重试。人工计时的前后端和工时表已移除，无需登记处理时长。

审校可能退回，也可能首版就通过。若达到预算停止，请看运行记录和具体问题，不反复点击生成或把停止状态当成功。

## 更新与负责人排错

本轮清理订单演示标记、重复商家身份列及旧工时表，其他机器更新代码后，先停止API/worker，执行 `uv run --project apps/server company-db-init`，再启动服务。当前本机已完成 `0012_intake_cleanup`，无需重复执行；已有数据保留。

若登录接口200，但进入工作台后订单列表500，日志出现 `column orders.product_details does not exist`，表示数据库未迁移，按上述步骤升级即可，不需要更换负责人密码。文档记录的是已确认的字段缺失故障；其他错误仍按具体日志排查。

## 自动检查

在项目根目录执行：

```text
uv run --project apps/server pytest apps/server/tests --run-db-tests -q
node scripts/test-stack.mjs
```

第一条需要独立测试库，覆盖后端规则、权限、持久化与恢复；第二条自动启动8100/3100隔离服务，运行浏览器完整双角色测试，完成后清理自己的进程，不改正在使用的本机或公网演示服务。首次需要安装测试浏览器：

```text
node apps/web/node_modules/@playwright/test/cli.js install chromium
```

macOS13可用已安装的系统Chrome，脚本会自动检测。不要同时运行两套使用同一测试库的测试。已有验收结果见 `PROGRESS.md`，环境与启动说明见根目录 `README.md`。
