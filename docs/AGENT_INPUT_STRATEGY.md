# 商品初审与内容产线

建单只有商品名字、商品明细、可选国内链接、参考图、补充说明与期望卖点五项。前端和API完成必填/格式检查，商家身份读取登录账号。获客顾问不再追索固定的材质、尺寸、数量、适用范围，也不要求逐项打勾；按实际类别分析服装、家居等商品。

## 当前架构

`Next.js表单 → FastAPI保存输入/图片及任务 → PostgreSQL任务队列 → LangGraph worker → 来源读取 → MiMo多模态初审 → Pydantic校验 → AgentRun与消息 → 负责人接单决定 → 研究/生成/审校 → 负责人放行 → 商家反馈/模拟发布`。

获客是受工作流调用的Python函数，不是自行操作网站的无限工具循环。流程状态、任务重试、权限、用量与版本由程序负责；MiMo负责资料分析、自然语言与内容方向。负责人始终决定是否接单，初审不能代替负责人批准。

## 初审实际读取什么

- 读取商品名字、原始明细、备注、最近卖家消息和已有属性记录。
- 最多向MiMo附上3张本单参考图的实际图像，先校验存储归属及文件摘要。可分析可见颜色、款式、主题及与文字是否一致，不能仅凭照片认定尺寸、面料或官方授权。
- 尝试读取一条公开HTTP(S)商品页，提取标题、描述与有界正文；逐跳校验公网地址并连接校验过的IP，限制端口、跳转次数、超时和响应大小。页面需要登录、验证码、反爬验证或读取失败时如实记录，继续分析已提供内容，不绕过登录，也不假称抓取成功。
- 图片和网页仍是来源材料，不能单独鉴定实物真伪。来源内容中的指令不能改变系统规则、审批权限或事实边界。

## 初审输出与展示

`IntakeAnalysis`包含自然中文回复、资料一致性判断、具体疑点及依据、图片观察、链接读取结果、带原文引用的`source_facts`，以及`content_brief`（商品类型、受众、卖点切入点、短英文标题和描述初稿）。程序只保留能逐字追溯的属性，不翻译引用或添加未知单位；实际未附图时不保存视觉观察，网页状态采用程序实际结果。

初审回复不再逐字段复述输入、罗列必备参数或附加程序模板问题。已有信息可展开表达和场景，未知性能不能补造。只有关键矛盾或无法理解商品时才问至多两个必要问题。商家偏好转为合理的受众、语气建议，避免攻击或贬低其他群体。

卖家可直接聊天或用自由文本补充说明；负责人在“Agent研究与内容产物”中看到初审与文案方向，审批前不再面对空白。初审处理期间接单按钮可见但禁用，完成后显示可用的批准/拒绝；缺少可选参数不会隐藏按钮。正式研究包在批准接单后自动生成，页面明确标注阶段。

## 下游约束

程序把卖家明确核实的属性和有原文依据的卖家描述分成`seller_confirmed`与`seller_provided`两类。产线兼容字段仍名为`confirmed_facts`，不代表所有描述均已鉴定；自动提取的第三方页面观察、授权或性能诉求不能自动成为本商品能力证据。声明继续引用事实ID，由独立审校和负责人放行。

研究、生成按实际类别与商家要求组织内容，不为补齐固定模板制造缺项。没有尺寸/数量时，图片可保留实际参考图并省略对应参数叠字；没有参考图可先接单和研究，图片阶段等待商家补图。当前图片制作是参考图排版，尚未接入外部生成式修图。

负责人仅可查看商家图片与版本素材；上传、删除由本单卖家执行，后端也拒绝只持负责人会话的修改。接单前商家更改参考图会触发新一轮初审；已在运行的旧结果不能覆盖新版本。

Amazon仍仅为明确标记的模拟刊登，未接入真实SP-API。订单演示模式、重复身份列、工时表、人工写研究证据和手动生产接口的清理见0012迁移及changelog；当前初审改造不增加数据库迁移，沿用持久化JSON、快照与任务记录。
